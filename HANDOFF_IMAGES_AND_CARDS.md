# Handoff: создание картинок/карточек/презентаций для уроков Silverwind

Дата составления: 2026-08-16. Всё ниже проверено по факту (файлы на диске), не по памяти модели.

---

## 1. Цель проекта

Для каждого урока Silverwind (аудио mp3) — сделать визуальные материалы в закреплённом фирменном стиле:

- **Карточка конспект+задание** — одна альбомная PNG/PDF-карточка с конспектом урока и практическим заданием.
- **Полноценная презентация** — многослайдовый PDF (10–12 слайдов: титул, несколько слайдов конспекта, слайды задания, закрывающая цитата).
- **Титульные карточки блоков** (отдельный формат) — заставки вида «БЛОК N / НАЗВАНИЕ» для оглавления курса/Miro-доски.

Картинки для иллюстраций — не генерируются заново, берутся из уже существующей библиотеки Leonardo AI (GPT Image 2 / Lucid Origin), см. раздел 6.

## 4. Локальный стиль / дизайн-система (закреплено, не менять без явной просьбы)

**Для уроков (карточка и презентация):**
- Фон `#0A0A0A`, металлик-акцент `#A8B4BE` → `#d0d8de` градиентом.
- **НЕ мятный `#89E6D8`, НЕ фиолетовый** — оба пробовались раньше и были отвергнуты («ужасный мятный», «ужасный фиолетовый»).
- Unbounded — заголовки/лейблы (вес 500, не жирнее), Inter — основной текст (вес 300).
- Никаких рамок/бордеров вокруг картинок и текстовых блоков — только `.label` и тонкая линия-разделитель.
- Шрифт должен быть крупным (после нескольких раундов правок финальные размеры: `p` 33px, `.label` 52px, `.bullets li` 28px — см. `build_deck_TEMPLATE.py`).
- Плотные слайды (много текста) — разбивать на пару слайдов (текст отдельно, тезисы/буллеты отдельно), не пытаться уместить всё на одном — иначе не хватает «воздуха».

**Для карточек блока (`blok-cards-template`) — ДРУГОЙ, отдельный стиль:**
- Тёмный почти-чёрный фон `#08080a` со звёздами (мелкие белые точки, разный размер/прозрачность) и двумя мягкими blur-глоу пятнами по углам.
- Акцент «БЛОК N» — **еле заметный фиолетовый металлик `#A79BC4`** (это НОВЫЙ закреплённый цвет для этого формата взамен мятного — решение принято в этой сессии, отличается от палитры карточек урока выше, не путать).
- Заголовок — Unbounded 700, крупный, металлик-градиент бело-серый (не такой же градиент, как в карточках урока — тут ярче/контрастнее, ближе к чистому белому).

## 5. Пайплайн рендера (общий для обоих форматов)

1. HTML-файл с инлайновым `<style>`, шрифты через `<link rel="stylesheet" href="fonts/local-fonts.css">` (self-hosted Unbounded+Inter, офлайн).
2. Рендер в PNG через headless Chrome:
   ```
   "/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless --disable-gpu --no-sandbox \
     --window-size=W,H --screenshot="out.png" --virtual-time-budget=3000 "file://.../file.html"
   ```
3. Для многослайдовой презентации — `urok-presentation-template/build_deck_TEMPLATE.py`: генерирует N HTML-файлов из Python-словаря слайдов, рендерит каждый в PNG (1600×1000), затем склеивает в один PDF через Pillow:
   ```python
   imgs = [Image.open(p).convert("RGB") for p in png_paths]
   imgs[0].save(out_pdf, "PDF", resolution=150.0, save_all=True, append_images=imgs[1:])
   ```
   **Важно:** склейка PNG→PDF через Pillow надёжнее, чем `--print-to-pdf` headless Chrome — у Chrome печать иногда создаёт лишнюю пустую страницу даже при точно подобранном `@page` размере (проверено, воспроизводилось дважды). Pillow-способ ни разу не подвёл.
4. Для одностраничной карточки — высоту канваса нельзя угадать сразу: рендерить с большим запасом высоты, затем Python/PIL построчно сканирует яркость пикселей, находит границу реального контента, канвас пересчитывается и рендерится заново точно по размеру.

## 6. Источник картинок

Библиотека Leonardo AI лежит на `~/Downloads/` и `~/Desktop/` (файлы `gpt-image-2_*` и `lucid-origin_*`, английское описание промта — в имени файла, искать по смыслу через `find ... | grep -iE "keyword1|keyword2"`). Стиль библиотеки — кристалл/стекло, чёрный фон, холодный подтон — подробно описан в памяти `project_leonardo_miro_style.md`.

**Каждую картинку перед вставкой в карточку нужно прогнать через скрипт выравнивания фона** (иначе виден шов вокруг картинки — исходные генерации не имеют пиксель-в-пиксель `#0A0A0A` фона):

```python
from PIL import Image
bg = (10, 10, 10); low, high = 10, 42
def match_bg(path, out_path):
    im = Image.open(path).convert("RGB"); px = im.load(); w, h = im.size
    for y in range(h):
        for x in range(w):
            r, g, b = px[x, y]; m = max(r, g, b)
            if m <= low: px[x, y] = bg
            elif m < high:
                t = (m - low) / (high - low)
                px[x, y] = (int(bg[0]+(r-bg[0])*t), int(bg[1]+(g-bg[1])*t), int(bg[2]+(b-bg[2])*t))
    im.save(out_path, quality=93)
```

Если картинка занимает мало места на большом чёрном холсте (много пустого поля вокруг маленького объекта) — дополнительно обрезать по фактическому bounding box содержимого (скан по яркости, найти minx/miny/maxx/maxy, обрезать с отступом ~60px), иначе объект будет выглядеть крошечным внутри карточки.

## 10. Какие ошибки были и как решались

- **Headless Chrome `--print-to-pdf` иногда создаёт лишнюю пустую страницу** даже при точном `@page` размере под контент. Решение — не использовать печать PDF из Chrome вообще, рендерить каждый слайд в PNG и склеивать через Pillow (`Image.save(..., save_all=True, append_images=...)`) — надёжно 100% случаев.
- **Файлы на Desktop иногда «улетают» в iCloud-заглушку** (`.Имя.pdf.icloud`) прямо во время сессии из-за синхронизации Desktop — после `cp` поверх существующего файла нужно подождать секунду и проверить `file <путь>` возвращает `PDF document`, а не ошибку «No such file». При конфликте синхронизации macOS иногда создаёт дубли `Имя 2.pdf`, `Имя 3.pdf` — их надо удалить и пересохранить под оригинальным именем.
- **mp3 уроков тоже могут быть iCloud-заглушками** — если `ls` показывает файл, а прямой доступ («No such file or directory») не работает, смотреть `.Имя.MP3.icloud` рядом и делать `brctl download "<путь без точки>"`, дождаться скачивания (может занять до минуты на большой файл).
- **Плотные слайды без «воздуха»** — если на одном слайде и объясняющий текст, и 3 буллета, и вывод-цитата — не помещается аккуратно, наезжает на шапку. Решение — всегда разносить на 2 слайда: текст-контекст отдельно, тезисы+вывод отдельно.
- **Картинка занимает мало места внутри карточки** — если исходная Leonardo-генерация имеет маленький объект на большом чёрном поле, `object-fit: contain` внутри узкого блока делает его почти невидимым — нужно сначала обрезать картинку по bounding box содержимого (см. раздел 6).
- **Float-обтекание текста ломает первое слово абзаца** — если картинка `float:right` стоит перед параграфом без своего текста-компаньона, первое слово абзаца может «оторваться» на отдельную строку. Решение — `<div class="clearfix"></div>` сразу после самостоятельной картинки.

## 11. Важные инструкции по стилю Silverwind (для картинок/карточек)

- Все палитры и стилевые решения — **закреплены явными указаниями Алины**, не додумывать заново. Если кажется, что «было бы красивее» с другим цветом/шрифтом — сначала спросить, не менять по своей инициативе.
- Мятный и фиолетовый (в контексте карточек урока) — **отвергнутые варианты**, не предлагать снова, если явно не попросят (как это произошло с новым фиолетовым металликом для карточек блока — это отдельное явное разрешение только для ЭТОГО формата, не переносить на карточки урока).
- Гарантированно нужен крупный шрифт — Алина несколько раз в течение сессии просила «увеличь шрифт ещё» с нарастающим раздражением; лучше сразу закладывать крупный размер, а не наращивать постепенно.
- Инструкции Алины часто идут голосом-в-текст с опечатками/слипшимися словами — самый надёжный способ разобрать неясную инструкцию: искать паттерн «вместо X — Y» (замени X на Y), он почти всегда там есть, даже если формулировка искажена.
- Контент карточек/презентаций брать **из полной транскрибации аудио урока** (whisper), а не додумывать по названию урока — конкретные примеры и метафоры лектора (Верочка/файлы, стакан/океан, проектор/экран) сильно повышают качество и узнаваемость материала.
